### Round 16 — a re-audit of a React application, and what its orchestrator sent back (2026-11-23)
- `extract_colors.py` keeps a token's value apart per scope (#41). Until now the last declaration won, whatever selector it stood under. On a stylesheet with opt-in reader settings on the root, such as `:root[data-contrast="high"]`, the file listed the values of those settings as the tokens, and by the count of that run's orchestrator none of its 52 failing pairs described the default theme. A declaration under `:root`, `html`, `body` or `:host` is now the base. One under a narrower selector or under a media query other than the colour scheme is a variant, listed with the value it replaces and with the failing pairs that change under it. A token that only refers to an overridden token changes with it when the variant is on the root itself; under a component it keeps the value it inherits. A token declared only inside components has the declaration under its plainest selector as its base. A selector is now read whole: one with its brace on the next line, or a list over several lines, used to lose its text, which made every scope look like the base. The words for a dark or light theme are the same for a scheme and for a variant, so `.dark-mode`, `.dark-theme` and an unquoted `[data-theme=dark]` are schemes, and a `style` element with a `media` attribute is the variant it says it is. Three smaller faults in the same file went with it. `light-dark()` with commas inside its arguments was split at the first comma. A shadow or gradient that contains a colour was reported as a colour that could not be resolved. And two status or brand colours of different families, such as `--good` on `--warn`, were paired as text on a surface, which that orchestrator counted as 30 of those 52 rows; they are now left out and counted. The files are walked in sorted order, so the result is the same on every machine. The script has a self-check of its own, `test_colors.py`, and a separate review found six of the faults above before the change was merged.
- The merge says what it used to pass over in silence (#42). The severity floor reaches a finding only through the IDs in the row of a persona's flow table, and nothing told a persona to put them there: in the re-audit both rows of a failed flow came out without an ID, no severity was raised, and nothing was reported. A failed or only-with-help row that names no finding, or only an ID that does not exist, is now a problem to resolve, so the phase check keeps phase 5 shut until the row names what stopped the persona. So is a result that is none of the protocol's six scores. The merge and the renderer read a result with one function now: a result that starts with "completed" is no failure whatever it goes on to mention, and the Dutch words count as scores. The persona protocol has a step for it and a fifth column in the flow table; a row in the old shape, with the ID in its obstacle cell, still works. A tier-2 finding without `tier_rationale` is a problem as well, unless it is minor, since that is the design impact the report prints; until now it surfaced at the very end, as a gap in the rendered report. A finding merged into another one hands over its rationale when the kept one has none. A persona's new finding has the field in its list. And `SKILL.md` says that a criterion turned to fail also needs the finding's ID in its `findings` list. The floor had no self-check before this; it has one now.
- A re-audit no longer calls a finding resolved because nobody filed it again (#43). The delta matches on the fingerprint, and a fingerprint is a slug an agent chose. In the re-audit the first delta said 50 resolved, 8 still open and 34 new; after its orchestrator matched 31 fingerprints by hand it was 19, 27 and 15, and four of those 19 had only not been looked at. An earlier finding without a match is now "not reported again", a group of its own in `delta.md` and in the report. Under each one the merge names the findings of this run that share two of criterion, file and a word of the slug. The orchestrator answers in `findings/_delta-map.json`: the finding of this run it is, or `"resolved"` once the code was checked. An entry that does not hold is a problem to resolve. What the earlier audit already did not see again stays on that list, with its title, until it is matched, found or checked. A delta written before this change had no such list, so its "resolved" is not taken as a check: what comes back from it is still open, not regressed. To have fewer to match, `build_briefs.py` gives each expert and the maximizer in a re-audit the earlier findings of its own area, one line each, with the instruction to reuse a fingerprint for a problem found again and to file nothing it did not see. A persona does not get them, because it walks before it reads findings. The phase check counts the map as input of the merge. The merge reads an earlier audit that is a bare list of findings, which is what an early version wrote and what it refused. The report prints an earlier finding by its title where it printed the fingerprint. A workspace with labels translated for another language needs the new heading added, and the renderer says which key is missing.
- The detector tells a page from a mention of one, and says what its count is made of (#44). A comment that named the `html` element in a component file was counted as a page without a language, and a Go test with a page in a string was reported as an interface embedded in source code, with the advice to audit its literals. A page is now a doctype, or two different parts of a document anywhere in the file, such as an `html` and a `head`; firmware that writes one tag per call still qualifies, and a file that names one element does not. Test files are not searched for embedded pages and no longer count as interface. The number that picks the audit size lists its parts and what it leaves out. In a project whose interface lives in component files, a plain script counts only when it touches the page: the DOM, a canvas, or markup of its own. In the re-audit that was the difference between 28 files and a full audit, and 21 and a lean one, by the figures of its orchestrator. In a project without component files the scripts are the interface and all count, as before. And when a backend marker sits at the root of the repository or beside a `package.json` that has something to start, the preflight and the detector say, in the same words, that the dev server may show the interface without its data and that the question to ask is how the whole application is started. A Gemfile beside a Jekyll config and a `go.mod` beside a Hugo config are not taken for a backend.
- The report no longer carries what only the scripts understand (#45). A finding is named by its report ID wherever an agent wrote the ID of its findings file: in the text of another finding, in a flow table, in a coverage note, and for a persona's finding too (`PER-low-vision-001` was left as it was, while `KBD-003` was replaced). The linter reports such an ID that is left. A table cell cut to length is not cut inside a code span any more; the open span made the linter report a slash on a row whose source was fine. Text of the interface between quotation marks passes the linter, arrow and all: the protocols asked for the label as the product shows it and the linter refused it, which was six of the thirteen lint errors of that run by its orchestrator's count. The hints in `report-prose.md` are written again on every run, with the text under them left as it is, and the command names a written section whose hint changed; before, a hint kept saying that no finding had landed in tier 3 after one had. In the flow table a persona has the name its block has, and appendix A names a lens and its method in the report language. Dutch: a contrast is "4,5 tot 1" in the token table as it is in the findings, where the table said "4.5 op 1". A labels file translated for another language needs the new keys `decimal`, `lens` and `method_word`; the command names what is missing and where to copy it from.
- The runtime scan sees content that is cut off where no scrolling reaches it, and looks at more than one narrow width (#46). The reflow check measured how far the page scrolls sideways at 320 pixels. A popover placed with a negative `left` does not widen the page, so in the re-audit a state whose content sat from 214 pixels left of the page to 44 pixels inside it came out as `reflowFails: false`, and only the personas found it. At 320 pixels, at the view's own viewport and at 768 and 1024 pixels (`--widths`, a 1280 pixel window at 167 and 125 percent zoom) the scan now lists text and controls whose box lies partly left of or above the start of the page; a row of the summary names the widths under `offscreenAt`. What waits wholly outside, a one pixel label, a hidden element, what an action scrolled out of a strip and the left side of a right-to-left page are not listed; open shadow roots are looked into, frames are not. A state that opens at its own viewport but not at another width, such as a menu button that only a phone shows, used to be reported as not reached although axe had scanned it: it is reached now, and the width is named under `notReachedAt`. The reason of a failed action names the action, without the value that was typed. A row also names the axe rules that failed with their number of elements, per colour scheme, which its orchestrator had to dig out of the files per view with a snippet of its own; and SKILL.md no longer says to read `summary.json` after the same rows were printed. `tooling.md` says that a selector may be text (`text=Graphs`, `button:text-is('Graphs')`) or the nth match, which that orchestrator found out in three extra calls for thirteen states. The scan has a self-check for the first time, `test_scan.mjs`, which serves its own pages and runs the real scan in a browser; a third job of the workflow runs it. Each extra width is one more load per view.
- Not measured: a stylesheet where a variant and a scheme set the same token with the same specificity, where the later rule wins in a browser and the variant wins in this table. A variant that names no scheme is laid over the dark values as well as the light ones. And no audit has run with the new file, so whether the visual lens reads the variants as intended is not known.

So that every listed problem can be closed, the merge changed with it. A `--previous` path that is not there or cannot be read is in both merge files as well as on stderr. A persona's finding without a level A or AA criterion is kept as an observation and noted, where an expert's is still a problem. A persona's place that is no file is kept as a place. In their place are 48 graders without a language model, on the report, the site's own files and the tool calls, and 4 judges on short text. The 48 are defined in `evals/test_graders.py`, which writes the grader files and checks them on a workspace built with the real merge and renderer: every seeded failure is found by its own grader and by no other. The README says what these graders cannot see.

- A ground-truth item may list several criteria, and a finding that cites any one of them counts. The social links without a name accept 2.4.4 as well as 4.1.2: a link without a name fails both, and two measured runs reported them under 2.4.4 and so counted as a miss. On the workspace the run above left, the detection is 23 of 24 by the new rule (#36).

### Round 11 — scripts take over what was left to memory (2026-11-16)
- `merge_findings.py` checks what a finding claims: the cited file, lines and snippet exist, the criterion is level A or AA with its name and level from the ownership table, and a stated contrast ratio is recomputed. A finding with no criterion and no best-practice marker is reported; the measured run had 8 of 42 such findings and flagged none (#8).
- `render_report_parts.py` writes the whole report as `REPORT.draft.md`, with every table and finding block filled from `_merged.json` and the prose left as marked gaps, instead of the orchestrator retyping each block (#9).
- The report can be written in any language. The fixed words live in `references/report-labels/<code>.json`; English and Dutch ship, any other language is translated once from a file the renderer writes into the workspace and then validated (#10).
- `lint_report.py` checks the finished report: no gap left, every report ID present once, and the read-aloud rules a script can decide (table width, heading levels, nested lists, symbols, slashes, ratios with a colon). Phase 6 ends when it exits 0 (#11).
- `check_phase.py` checks at the end of phases 3 to 6 that the phase left what the next one builds on: every expert's file, a status for every criterion it owns, a merge newer than its inputs, briefs newer than the stack profile, a report that passes the linter. `build_briefs.py` writes the list of agents it reads, and ends each lens brief with the start of that agent's findings file (#12).
- `preflight.py` does Phase 0 in one read-only command and sets the workspace up in a second. A re-audit moves the whole earlier audit aside, a run in progress stays, nothing is deleted, and `.gitignore` is only appended to (#13).
- The merge separates what it settled itself (`notes`) from what needs a decision (`problems`). Snippets are compared with whitespace next to punctuation removed, a persona's prose is no longer looked up as a quote, and a coverage reason is read from `reason` as well as `note` (#14).
- `SKILL.md` follows the order of the work: the stack profile and the static scans open Phase 2, the persona selection is made in Phase 3, a finding is split into two tiers in 4c. Subagents are stated as the rule for full, lean and mini audits. The description names the focused review. `scan_patterns.py` counts forms and form controls, which decide mini or lean (#16).
- Each brief carries only the reference parts its reader acts on, about 12 percent less text. The cuts stop the build when a reference no longer has the section or field they name (#17).
- `LICENSE` added: MIT, as `plugin.json` and the README already said (#15).
- Eight self-checks next to the scripts (`test_walk`, `test_merge`, `test_grade`, `test_render`, `test_lint`, `test_phase`, `test_preflight`, `test_briefs`), plain asserts, run with `python3 skills/tiered-a11y-audit/scripts/test_<name>.py`.

### Round 6 — feedback from a themed Hugo site (lean mode)
- **axe no longer runs twice on one page with a colour-scheme flip**: each scheme gets its own browser context and page load. The old behaviour fabricated serious contrast violations near 1.0 to 1 on every page of any site with a `dark` class.
- `--steps` actions type real keystrokes (`type`/`fill` via `pressSequentially`), accept a per-state `viewport` and `force`, and a failed state is reported instead of dropped. Action shapes spelled out.
- Coverage is routed to the criterion's owner regardless of which findings file reported it (lean and mini modes); conflicts only when two files disagree. Persona `wcag` citations are advisory and listed separately instead of overturning the owner's status.
- Detector excludes build output, lists packages found only in vendored code separately, and prints the count of project-owned UI files that drives the mode choice.
- `fix.ownership` (project / override / upstream / accepted) with optional tool exceptions; writable directories established in Phase 2; "Needs an upstream change" and "Accepted exceptions" blocks in the report; prior a11y claims in the repo are re-measured.
- Mini mode (two merged experts, two personas); cost quoted per mode; skill and scratch paths live in the stack profile so subagent prompts are short.
- Hugo playbook expanded (i18n per language, `.IsMenuCurrent`, `--printI18nWarnings`/`--panicOnWarning`, anchors inside headings).
- Cognitive persona names sentences instead of rewriting them.
